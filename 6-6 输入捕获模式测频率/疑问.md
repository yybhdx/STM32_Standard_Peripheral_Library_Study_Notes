# STM32 输入捕获与 PWMI 模式的对比及原理分析

## 1. 您的理解是否正确？
**您的理解完全正确！**

您的理解非常精准。PWMI（PWM 输入）模式确实是在普通输入捕获（Input Capture）模式的基础上，通过**将两个内部捕获通道映射到同一个物理输入引脚**来实现的。
* **主通道（通常是通道 1）**：捕获**上升沿**（用于测量整个周期/频率），并利用从模式（Slave Mode）自动将计数器（CNT）复位清零。
* **副通道（通常是通道 2）**：配置为相反的极性，捕获**下降沿**（用于测量高电平时间），但不复位计数器。

通过这两个通道获取的值，就可以计算出波形的**占空比**：
$$\text{占空比} = \frac{\text{高电平时间 (CCR2)}}{\text{整个周期时间 (CCR1)}} \times 100\%$$

---

## 2. 输入捕获模式 与 PWMI 模式 的对比

| 对比维度 | 普通输入捕获模式 (Input Capture) | PWMI 模式 (PWM Input) |
| :--- | :--- | :--- |
| **占用通道数** | 占用 1 个定时器通道 (例如 CH1) | 占用 **2 个**定时器通道 (例如 CH1 和 CH2) |
| **占用引脚数** | 占用 1 个物理引脚 (例如 PA6) | **同样仅占用 1 个物理引脚** (两个内部通道连接到同一个引脚) |
| **触发极性** | 单一边沿（上升沿或下降沿） | 两个通道极性相反（一个上升沿，另一个下降沿） |
| **测量指标** | 主要用于测量**频率**或周期 | 同时测量**频率**和**占空比** |
| **寄存器分工** | CCR1 记录整个周期的计数 | CCR1 记录周期计数，CCR2 记录高电平计数 |

---

## 3. PWMI 模式的工作步骤拆解 (通俗中文版)

我们以信号从 **PA6** 引脚输入，使用定时器 3（TIM3）的通道 1（CH1）和通道 2（CH2）为例，说明其工作流程：

* **第一步：内部信号分流（一引脚双通道）**
  虽然我们在外部只用一根导线连接到 PA6，但在 STM32 内部，可以通过配置将该引脚的输入信号**同时分流**给通道 1 (IC1) 和通道 2 (IC2)。

* **第二步：配置相反的捕获边沿**
  * 将通道 1 (IC1) 配置为**上升沿**触发捕获。
  * 将通道 2 (IC2) 配置为**下降沿**触发捕获。

* **第三步：结合“从模式”实现 CNT 自动清零**
  我们将通道 1 的上升沿信号作为触发源（Trigger），去触发定时器的“从模式复位”功能：
  * **当信号出现上升沿时**（一个周期的开始）：
    1. 计数器（CNT）的值被锁存（拷贝）到捕获寄存器（CCR1）中。
    2. 紧接着，硬件自动把 CNT 清零，让它从 0 开始重新往上累加计数。
  * **当信号出现下降沿时**（高电平结束，低电平开始）：
    1. 计数器（CNT）在继续累加数数，并未停止。但由于触发了下降沿，通道 2 的捕获寄存器（CCR2）会立刻锁存此时的 CNT 计数值。
    2. **注意**：此时 CNT **不会清零**，它会继续数数。这个 CCR2 的值就是**高电平持续的计数时间**。
  * **当信号再次出现上升沿时**（一个周期的结束，下一个周期的开始）：
    1. 通道 1 再次被触发，当前的 CNT 值（即整个周期的总计数值）被锁存到 CCR1 中。
    2. 从模式复位再次生效，CNT 自动清零，开始下一个周期的计数循环。

* **第四步：软件读取与计算**
  利用读取出来的两个寄存器数值，即可直接算出：
  * **频率** = $\frac{\text{计数器标准频率}}{\text{CCR1} + 1}$
  * **占空比** = $\frac{\text{CCR2} + 1}{\text{CCR1} + 1} \times 100\%$

## 4. 为什么 频率 = 计数器标准频率 / (CCR1 + 1)？

很多初学者容易在这里产生疑问，我们将这个公式拆解开来看：

### 4.1 公式推导原理

1. **什么是频率和周期？**
   * **周期 ($T$)**：波形完整变化一次所需要的时间（单位：秒）。
   * **频率 ($f$)**：1秒钟内波形变化的次数（单位：Hz）。
   * 它们的关系为：$$f = \frac{1}{T}$$
   因此，只要我们通过计数器测量出波形的**周期 $T$**，就可以通过取倒数算出**频率 $f$**。

2. **计数器是如何测量时间的？**
   假设计数器的标准计数频率为 $f_{clk}$（例如 1000Hz，即 1 秒钟自增 1000 次），那么计数器每增加 1，代表经过的微小时间间隔为：
   $$t_{step} = \frac{1}{f_{clk}} = 0.001\text{秒} = 1\text{毫秒}$$

3. **捕获寄存器 (CCR1) 里的值代表什么？**
   在上升沿触发时，计数器 CNT 硬件清零并重新开始数数。当下一个上升沿到来时，CNT 的计数值被存入 CCR1 中。
   如果 CCR1 读取出来的值是 $N$：
   * **为什么要加 1？**
     因为计数器是从 `0` 开始数数的。从 `0` 数到 $N$，其实一共数了 $N - 0 + 1 = N + 1$ 个数（计数周期数）。
     例如：从 0 数到 9，一共数了 10 个数。
   * 因此，整个波形周期 $T$ 的实际时间就是：
     $$T = (CCR1 + 1) \times t_{step} = (CCR1 + 1) \times \frac{1}{f_{clk}}$$

4. **最终的频率公式**
   把周期 $T$ 代入频率公式 $f = \frac{1}{T}$ 中：
   $$f = \frac{1}{T} = \frac{1}{(CCR1 + 1) \times \frac{1}{f_{clk}}} = \frac{f_{clk}}{CCR1 + 1}$$

---

### 4.2 实例解析 (以您的疑问为例)

在您的设想中提到了“捕获的 PWM 波周期为 1ms，计数器周期为 1s”。
> [!NOTE]
> 这里的 1ms 和 1s 都是指**时间周期**，对应的频率分别是 1000Hz 和 1Hz。
> 如果计数器 1 秒钟才加 1 次，而 PWM 波 1 毫秒就结束了一个周期，那么计数器还没来得及加 1，PWM 波就已经变化完了，此时是无法测量的。**测量的前提是：计数器的自增频率必须远高于待测信号的频率。**

为了让这个例子成立，我们将时间尺度对调一下（即让计数器变快，待测信号变慢）：

* **假设已知条件**：
  * **待测 PWM 波周期**：$T_{pwm} = 1\text{秒}$ (对应的实际频率 $f_{pwm} = 1\text{Hz}$)
  * **计数器标准计数周期**：$T_{clk} = 1\text{毫秒}$ (即计数频率 $f_{clk} = 1000\text{Hz}$，每 1ms 计数器加 1)

* **测量过程**：
  1. 第一个上升沿到来，CNT 硬件清零并开始数数（从 0 开始）。
  2. 过了 1 秒钟后（即一个完整的 PWM 周期结束），第二个上升沿到来。
  3. 在这 1 秒钟的等待中，因为每 1 毫秒计数器加 1，所以计数器总共累加了 1000 次。
  4. 计数器从 0 累加了 1000 次，最后的数值是 **999**。这个值被锁存到 **CCR1** 中，即 $CCR1 = 999$。
  5. 代入公式计算：
     $$\text{频率} = \frac{f_{clk}}{CCR1 + 1} = \frac{1000}{999 + 1} = 1\text{Hz}$$
     计算得到的频率刚好是 1Hz，对应的周期正是 1 秒，完全吻合！

## 5. 中断函数为什么要设置为“弱函数”？

您的理解中，关于“**弱函数是为了方便我们自己定义和使用**”这一半是**完全正确**的；但关于“**默认使用会打断 CPU 阻碍运行**”这一半存在一些**小误解**。

### 5.1 什么是弱函数（Weak Function，在 Keil/汇编中用 `[WEAK]` 标识）？

在 STM32 的启动文件（如 `startup_stm32f10x_md.s`）中，所有的中断服务函数（比如 `USART1_IRQHandler`、`TIM3_IRQHandler`）都默认被声明为**弱函数**。

* **链接器的规则**：如果用户**没有**在自己的 C 文件里写这个同名函数，链接器就会编译并使用启动文件里**默认的**“弱函数”；一旦用户**自己定义**了同名的中断函数，链接器就会优先使用用户定义的函数，并自动把原来的“弱函数”丢弃。
* **主要目的**：**极大地方便用户重写**。您不需要去修改底层的、晦涩难懂的汇编启动文件，只需要在自己的 C 文件中写一个一模一样的函数，就能直接接管该中断的处理逻辑。

---

### 5.2 澄清一个误解：中断是否会打断 CPU？

> [!IMPORTANT]
> **中断是否会打断 CPU 运行，完全取决于您在硬件/寄存器上是否“开启（使能）”了该中断，而与该函数是不是弱函数无关。**

1. **不开启，绝不打断**：
   即使一个中断函数被写得非常复杂，只要您没有在代码中调用类似于 `NVIC_Init()` 和外设的 `ITConfig` 函数去**使能**该中断，硬件就不会产生中断请求，CPU 也就绝对不会被它打断。
2. **默认的弱函数是“安全备胎”**：
   如果您的程序在硬件上不小心使能了某个中断（比如串口接收中断），但您在 C 代码中**忘记写**对应的中断处理函数了：
   * **如果没有弱函数**：CPU 触发中断后，在中断向量表里**找不到函数入口**，程序会直接“**跑飞**”或**崩溃**（进入 HardFault 硬件错误状态）。
   * **因为有了弱函数**：CPU 会去执行启动文件中默认提供的那个弱函数。默认的弱函数通常内部只有一句死循环（汇编里的 `B .`，即跳转到当前行），相当于把程序“卡死”在这里。虽然程序卡住了，但这是一种**安全保护机制**，防止程序在未处理中断的状态下带着错误逻辑继续乱跑，同时也非常方便您通过仿真器进行调试定位。

### 6.2 同一个通道可以同时使用输入捕获和输出比较吗？

> [!WARNING]
> **不可以。同一个定时器的同一个通道，在同一时间只能工作在“输入捕获”或者“输出比较”模式中的一种，两者是物理互斥的。**

* **原因**：每个通道的引脚电路上只有一套核心的**捕获/比较寄存器（CCR）**：
  * 在**输出比较**模式下，这个寄存器用作**比较值寄存器**，内部数值与 CNT 计数器比较，决定输出电平的翻转。
  * 在**输入捕获**模式下，这个寄存器用作**锁存寄存器**，在输入信号触发（比如上升沿）时，将当前 CNT 计数器的值锁存拷贝下来。
* 因此，这套硬件电路同一时刻只能二选一。

---

### 6.3 想要同时使用两种功能该如何做？

**您的理解完全正确：可以使用同一个定时器的其他通道，或者使用其他定时器。**

1. **方案一：使用同一个定时器的不同通道（如 TIM3）**
   * **实现方式**：例如，您可以将 `TIM3_CH1` 配置为**输入捕获**，而将 `TIM3_CH2` 配置为**输出比较**。
   * **限制条件**：同一个定时器的所有通道**共享同一个时基单元**（即相同的计数周期 ARR 和预分频 PSC）。这意味着，它们工作时的**计数频率 and 自动重装周期必须是完全相同的**。如果您对输出 PWM 的频率和输入捕获的测频频率没有独立配置的需求，这个方案非常节省硬件资源。
2. **方案二：使用不同的定时器（如本项目中的 TIM2 和 TIM3）**
   * **实现方式**：像本项目一样，用 `TIM2_CH1` 输出比较来发 PWM，用 `TIM3_CH1` 输入捕获来测频。
   * **优势**：两个定时器完全独立，它们拥有各自的时基单元（各自的 PSC 和 ARR）。因此，你可以自由地将 TIM2 的 PWM 频率设置为 1kHz，而将 TIM3 的捕获频率（计数时钟）设置为 1MHz，彼此互不干扰，灵活性最高。

## 7. 输入捕获与输出比较的通道号需要匹配对应吗？

**完全不需要！**

这是一个非常常见的误区。您可以将**任意定时器的任意通道**输出的 PWM 波，用**导线**连接到 `TIM3_CH1` 进行输入捕获，两边的通道号完全不需要一致。

### 7.1 为什么通道号不需要一致？

* **外部物理连接性质**：
  发送端（发波）与接收端（捕获）之间，是通过**外部的物理导线（如杜邦线）**进行物理连接的。
  * **发波端**只管在自己对应的引脚上输出电平高低变化，不关心谁来读它。
  * **捕获端（PA6，即TIM3_CH1）**只负责检测 PA6 这个物理引脚上的电平跳变，它**无法得知，也完全不在乎**这个电平是由哪一个定时器、哪一个通道产生的。它甚至可以测量由外部信号发生器产生、或者由按键手动按出来的信号。
* **生动的例子**：
  这就像**寄快递**：
  * 寄件人（发波端）住在“2号楼的1号房 (TIM2_CH1)”。
  * 收件人（捕获端）住在“3号楼的1号房 (TIM3_CH1)”。
  * 只要用快递（导线）把两边连起来，收件人就能收到东西。
  * 寄件人即使搬到“2号楼的2号房 (TIM2_CH2)”或者“1号楼的4号房 (TIM1_CH4)”，只要导线依然连着收件人的房间，收件人照样能正常接收，完全不受影响。

### 7.2 结论
* **完全可以使用** `TIM2_CH2`、`TIM1_CH3` 等任意通道输出的波形，并用导线连接到 `TIM3_CH1` (PA6) 进行测量。
* 通道号（Channel 1、Channel 2 等）只是定时器**内部**对各组寄存器和引脚的编号。**跨定时器**以及**通过外部导线物理连接**时，通道号之间**没有任何的绑定或对应关系**。
